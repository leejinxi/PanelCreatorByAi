# 本地 MCP 回环 PoC 阶段性报告

日期：2026-09-09
状态：阶段 1–4 已完成；真实 CAD 接入尚未开始

## 目标

在无法取得公司 CAD API 资料的条件下，使用个人 PC 自拟契约验证 Python Agent 与 MCP 的本地 STDIO 通信原理。此 PoC 不连接真实 CAD，不证明实验字段与公司 API 一致。

## 已完成阶段

### 阶段 1：实验契约

- 文件：`contracts/FULL_contract_with_data.json`
- 版本：`0.1-poc`
- 状态：`confirmed`
- 仅定义 `create_panel`。
- 输入字段：`referenceName`、`thicknessMm`、`material`、`boundaries`。
- Mock 场景：默认成功、`REFERENCE_PLANE_NOT_FOUND`、`CAD_UNAVAILABLE`。
- 已加强空白字符串拒绝及成功/失败输出互斥。

### 阶段 2：Mock MCP STDIO Server

- `mcp_mock/contract.py`：读取已确认契约并校验输入/输出 Schema 和样例。
- `mcp_mock/server.py`：注册 Tool、校验参数、匹配数据并返回 `structuredContent`。
- 已使用真实 MCP SDK 验证 `initialize`、`tools/list` 和 `tools/call`。

### 阶段 3：MCP Client 与 CAD Backend

- `mcp_client/stdio_client.py`：以当前 Python 启动独立 STDIO Server 子进程。
- `tools/mcp_cad_backend.py`：实现现有 `CadBackend` 接口。
- 字段映射：`reference_plane -> referenceName`、`thickness -> thicknessMm`。
- MCP 业务失败经 `CreatePanelTool` 转换为 `CadExecutionResult`。
- 已覆盖 `MCP_TIMEOUT`、`MCP_UNAVAILABLE`、`MCP_INVALID_RESPONSE` 和业务错误码。

## 当前未完成

当前默认路径（`CAD_BACKEND=mock`）仍是：

```text
LangGraph -> create_panel() -> MockCadBackend
```

MCP Contract Mock 路径已接通并完成真实 Qwen 成功/澄清人工验收：

```text
浏览器 -> FastAPI -> LangGraph -> Ollama
  -> create_panel() -> McpCadBackend
  -> MCP STDIO Server -> FULL_contract_with_data.json
  -> Web 页面
```

具体缺口：

- 公司真实 CAD Adapter/MCP Server 尚未接入。
- MCP 后端当前每次调用都会启动一次 STDIO Contract Mock 子进程，尚未做会话复用。
