# 本地 MCP 演示操作手册

日期：2026-09-10

## 演示目标

展示自然语言请求经过浏览器、FastAPI、LangGraph、本地 Ollama、MCP STDIO Contract Mock，再返回浏览器的完整链路。当前结果是模拟执行，不连接或修改真实 CAD 工程。

## 一键启动

先在旧网页服务终端按 Ctrl+C 停止服务，再从仓库根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start_mcp_demo.ps1
```

看到启动提示后访问 `http://127.0.0.1:8000`。页面顶部应显示 `MCP Contract Mock · CAD execution is simulated`。

## 固定演示流程

### 场景一：完整请求成功

输入：

```text
在第100肋位创建14mm厚AH36板架，边界 >SL10
```

预期页面依次显示解析、校验和 CAD 创建成功；定位面是 `FR100`、厚度是 `14`、材料是 `AH36`，并返回模拟对象 ID `mock-mcp-panel-001`。

### 场景二：缺少边界并澄清

点击“开始新任务”，输入：

```text
在第100肋位创建14mm厚AH36板架
```

预期校验步骤提示补充至少一条边界，CAD 步骤跳过且没有对象 ID。继续输入：

```text
边界 >SL10
```

预期累积上下文后完成模拟创建。

## 演示说明

- 现场主流程只演示成功和多轮澄清，这两种输入已经在真实 Qwen 上验证。
- `REFERENCE_PLANE_NOT_FOUND` 和 `CAD_UNAVAILABLE` 已通过真实 MCP STDIO 自动化测试验证。英文哨兵值可能被 Qwen 丢弃，因此不作为固定自然语言演示输入。
- 页面执行期间锁定输入、示例、清空和新任务入口，避免中途改写状态。
- 页面等待超过 150 秒后停止等待，并提示服务端任务可能仍在执行，避免立即重复创建。

## 演示前检查

```powershell
conda run -n ai_cad_agent python --version
ollama list
conda run -n ai_cad_agent python -X utf8 run_tests.py
```

Python 应为 3.11，模型列表应包含 `qwen2.5:7b`。


## 透明执行台观察重点

成功场景中确认：

- 五个节点全部为绿色成功状态。
- Local Qwen 显示模型推理耗时。
- MCP STDIO 显示 tools/call 和 MCP 总耗时。
- MCP Inspector 显示 contract_version=0.2-poc；referenceName、thicknessMm、material 及 boundaries 数组与结构化参数一致。
- Contract Mock 返回 mock-mcp-panel-001。
- 页面标明 MCP Contract Mock，执行结果标明模拟创建和模拟对象 ID；不展示板架示意图。

缺边界场景中确认：

- LangGraph 和 Pydantic Schema 显示 attention。
- MCP STDIO 和 Contract Mock 显示 skipped。
- MCP Request/Response 均为空，证明未调用 CAD。

## 契约与排障

脚本显式使用已确认的本地实验契约 contracts/boundary_list_0.2.json，并覆盖旧终端中的 Direct Mock 设置。无需单独启动 MCP Server，客户端自动创建 STDIO 子进程。保持网页服务终端运行，退出用 Ctrl+C。

若第四步仍显示 Direct Mock，请确认旧服务已停止，并刷新到新服务。若显式指定旧四向契约，返回 MCP_CONTRACT_INCOMPATIBLE；指定未确认草案返回配置错误，不会自动回退到 Direct Mock。

非法边界可输入“在FR100创建14mm厚AH36板架，边界 >=SL10”：应澄清且 Request/Response 为空。MCP 超时、后端异常和协议错误通过自动化故障注入验证，不保证自然语言稳定触发这些故障。

当前 Contract Mock 依据固定场景响应，不查询边界目标是否存在；固定对象 ID 仅用于演示，不代表真实建模或持久化结果。
